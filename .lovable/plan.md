# خطة توليد الدروس وتنظيمها في HN-AI

## الوضع الحالي (تم التحقق منه)
- الهيكل الهرمي موجود: programs → levels → courses → chapters → units → lessons → lesson_blocks + questions/question_options.
- المحتوى الفعلي في قاعدة البيانات ضعيف جدًا: برنامج 1، مستويان، مقرران، 3 فصول، 3 وحدات، 6 دروس، 13 بلوك، 7 أسئلة فقط.
- يوجد بالفعل `generateLessonDraft` في `src/lib/api/studio.functions.ts` يولّد درسًا واحدًا بـ Gemini Flash (JSON صارم: blocks + questions)، لكنه لا يحفظ تلقائيًا ولا يولّد مناهج كاملة.

الفجوة: لا يوجد مولّد **منهج** (مسار كامل من مقرر → فصول → وحدات → دروس)، ولا توليد دفعات، ولا مراجعة/نشر منظّم.

## 1) مولّد المخطط المنهجي (Curriculum Outline)
دالة جديدة `generateCourseOutline`: تُعطى (الموضوع، المستوى، اللغة، عدد الفصول/الوحدات/الدروس المستهدف) فتُعيد JSON:
- عنوان المقرر ووصفه وأيقونته ولونه ودرجة صعوبته
- فصول ← وحدات ← عناوين دروس مع ملخص قصير ومدة و XP لكل درس
تُحفظ كلها بحالة `draft` مع `order_index` مرتب، دون توليد المحتوى بعد.

## 2) توليد محتوى الدرس على دفعات
- `generateLessonContent(lessonId)`: يستدعي المولّد الحالي مع سياق الدرس (عنوان المقرر/الفصل/الوحدة + عناوين الدروس المجاورة) لتفادي التكرار، ثم يحفظ البلوكات والأسئلة عبر `saveLessonContent`.
- `generateUnitLessons(unitId)`: طابور تسلسلي داخل الوحدة مع فاصل زمني بسيط لتجنّب حد 429، وإرجاع تقرير نجاح/فشل لكل درس.
- إعادة التوليد لدرس واحد تستبدل البلوكات القديمة بالكامل.

## 3) الجودة والتحقق
- تحقق Zod على مخرجات النموذج: 4–7 بلوكات، 3–5 أسئلة، 4 خيارات لكل سؤال وإجابة صحيحة واحدة بالضبط.
- محاولة إعادة واحدة تلقائية عند فشل التحليل أو خرق القواعد.
- منع تكرار عناوين الدروس داخل نفس المقرر (فحص قبل الإدراج).
- كل عملية توليد تُسجَّل في `audit_logs` عبر `log_action`.

## 4) واجهة الاستوديو في لوحة التحكم
صفحة جديدة `console/generator` (مرئية لـ admin/editor فقط) بثلاث خطوات:
1. **تحديد**: الموضوع، اللغة (ar/en)، المستوى، حجم المنهج، المسار/المستوى الأب.
2. **مراجعة المخطط**: شجرة قابلة للتحرير (تعديل/حذف/إعادة ترتيب العناوين) قبل الحفظ.
3. **التوليد**: شريط تقدّم لكل درس مع حالات (بانتظار / يولّد / تم / خطأ + إعادة محاولة).
وفي صفحة `console/lessons`: أزرار «ولّد المحتوى» و«أعد التوليد» لكل درس، وتوليد جماعي للوحدة.

## 5) التنظيم والنشر
- كل ما يُولَّد يبقى `draft` ولا يظهر للطلاب.
- زر «نشر» على مستوى الدرس/الوحدة/الفصل/المقرر يحوّل الحالة إلى `published` بشكل متسلسل هابط.
- إعادة ترتيب بالسحب مع تحديث `order_index`.
- مؤشر اكتمال لكل درس (بلوكات؟ أسئلة؟) لتمييز الدروس الفارغة.

## 6) ملء المحتوى الأولي
توليد مقررات البداية حسب مخطط المنصة: أساسيات AI، هندسة الأوامر، بايثون للمبتدئين، تعلم الآلة، أدوات AI العملية، Linux، قواعد البيانات، الأمن السيبراني — بمستويين لكل مسار، مع مراجعة يدوية قبل النشر.

## تفاصيل تقنية
- كل الاستدعاءات عبر `createServerFn` + `requireSupabaseAuth` + فحص `can_edit_content`، والمفتاح `geminiflash` يُقرأ داخل الـ handler فقط.
- `responseMimeType: application/json` مع مخطط استجابة صارم لتقليل أخطاء التحليل.
- التوليد الجماعي يتم بطلب واحد لكل درس من المتصفح (تسلسليًا) لتفادي مهلة الـ Worker، وليس في طلب خادم واحد طويل.
- لا حاجة لتعديلات في المخطط القاعدي؛ الجداول الحالية كافية.
