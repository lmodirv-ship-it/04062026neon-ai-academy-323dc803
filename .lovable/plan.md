# خطة إكمال منصة HN-AI

## الوضع الحالي (تم التحقق منه)
- 47 صفحة موجودة فعليًا، منها 27 صفحة داخل لوحة التحكم `/console`.
- 19 جدولًا في قاعدة البيانات: البرامج → المستويات → الدورات → الفصول → الوحدات → الدروس → البلوكات، مع الأسئلة والتقدّم والمدونة والزوار والسجلات والأدوار.
- نظام الأدوار يعمل: owner / admin / editor / student، والشريط الجانبي يظهر حسب الصلاحية.

الفجوة ليست في عدد الصفحات بل في العمق: لا يوجد فيديو، لا شهادات حقيقية، لا مشاريع مُسلَّمة، لا اشتراكات، لا دردشة ذكية، ولا منتدى.

## طريقة العمل المتفق عليها
- الصفحات المفصلية (صفحة الدرس، لوحة الطالب، الدردشة، الشهادة، صفحة الأسعار): أعرض **3 اقتراحات تصميم** لتختار واحدًا قبل الكود.
- بقية الصفحات: أبنيها مباشرة بنفس الهوية (Neon Royal + ذهبي HN-AI) دون انتظار.
- الاستضافة تبقى على Lovable مع النطاق hn-ai.store؛ ملف ترحيل الـVPS يُكتب في النهاية فقط.

## الدفعة 1 — تجربة الطالب (الأولوية القصوى)

**قاعدة البيانات**
- `lesson_blocks`: دعم نوع `video` (رابط + مدة + غلاف) و `embed`.
- جداول جديدة: `enrollments` (تسجيل الطالب في مسار)، `project_submissions` (تسليم المشاريع + مراجعة المدرّب)، `certificates` (رقم تسلسلي، رابط تحقّق عام، تاريخ الإصدار)، `notifications` للطالب.
- سياسات RLS: الطالب يقرأ ويكتب بياناته فقط، المدرّب يقرأ تسليمات دوراته، والشهادة قابلة للتحقّق العلني بالرقم فقط.

**الصفحات**
- `/learn/$slug` تُعاد بناؤها: مشغّل فيديو + فقرات قراءة + سؤال تفاعلي بين البلوكات + شريط تقدّم لزج + زر "الدرس التالي" + تشجيع صوتي/بصري عند الإجابة الصحيحة.
- `/courses` مكتبة دروس بفلترة (المستوى، الصعوبة، المدة، الحالة).
- `/courses/$slug` صفحة الدورة: المنهج الكامل بالفصول والوحدات + نسبة الإنجاز + زر التسجيل.
- `/quiz/$lessonId` اختبار كامل بنتيجة ودقّة وإعادة محاولة.
- `/projects/$id` تفاصيل المشروع + رفع التسليم.
- `/certificates` قائمة شهادات الطالب، و`/verify/$code` صفحة تحقّق عامة.
- `/dashboard` يُطوَّر: الاستمرارية، الخطوة التالية، آخر الدروس، الشارات.

**معاينات تصميم**: صفحة الدرس، لوحة الطالب، الشهادة.

## الدفعة 2 — الاشتراكات والدفع
- تفعيل مدفوعات Lovable المدمجة (Stripe) بعد فحص الأهلية — يتطلب خطة Pro.
- جداول: `plans`, `subscriptions`, `invoices`, `coupons`.
- `/pricing` صفحة أسعار (مجاني / احترافي / مدى الحياة) + `/billing` داخل الحساب.
- بوابة محتوى: الدروس المدفوعة تُقفل بشارة أنيقة بدل الإخفاء، مع تحقق على الخادم لا في المتصفح.
- ربط تبويبات `/console/plans` و`/console/transactions` و`/console/coupons` ببيانات حقيقية.

**معاينة تصميم**: صفحة الأسعار.

## الدفعة 3 — أدوات HN-AI الذكية
- `/chat` دردشة HN-AI بالبث المباشر (streaming) مع حفظ المحادثات في جدول `ai_conversations` + `ai_messages`.
- `/tools/image` مولّد صور، `/tools/analyze` تحليل ملف/نص وتلخيصه، وتطوير `/playground`.
- حدود استخدام يومية حسب الخطة (جدول `ai_usage`) لحماية الرصيد، وعرضها للمستخدم بوضوح.
- `/console/api` يعرض الاستهلاك الفعلي لكل مستخدم وأداة.

**معاينة تصميم**: واجهة الدردشة.

## الدفعة 4 — لوحة المعلم والمجتمع
- دور `instructor` جديد + مساحة `/teach`: دوراتي، طلابي، تسليمات بانتظار المراجعة، أسئلة الطلاب.
- منتدى: `forum_topics`, `forum_replies`, تصويت، وضع "أفضل إجابة"، إشراف من اللوحة.
- إشعارات داخل المنصة + بريد ترحيبي وتذكير الاستمرارية.
- لوحة صدارة موسمية وشارات إنجاز.

## المرحلة الأخيرة
- مراجعة أمنية شاملة (RLS، الصلاحيات، حدود الإدخال) واختبار المسارات الحرجة.

- توثيق `VPS_DEPLOY.md` لترحيل مستقبلي إلى Ubuntu.

## ملاحظات تقنية
- كل قراءة/كتابة حساسة عبر `createServerFn` مع `requireSupabaseAuth`؛ الصفحات العامة عبر عميل القراءة العام.
- الفيديو: تخزين الروابط (YouTube/Vimeo/رابط مباشر) لا الملفات في البداية؛ رفع الملفات يحتاج تخزينًا مدفوعًا لاحقًا.
- الشهادات تُولَّد كصور/PDF من قالب على الخادم مع رمز تحقّق فريد.
- الذكاء الاصطناعي يعمل على مفاتيح Gemini المحفوظة حاليًا مع حدود استخدام.

## عن عدد الصفحات
120–180 صفحة مستقلة ليست الهدف الصحيح؛ المنصات العالمية تبني ~40 صفحة حقيقية + صفحات ديناميكية بالمعرّف (كل درس، كل دورة، كل شهادة، كل موضوع منتدى صفحة بذاتها). بهذا المنطق ستتجاوز المنصة 200 عنوان URL فعلي بعد الدفعة الثالثة دون تكرار أو حشو.
