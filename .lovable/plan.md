
# خطة تطوير HN-AI — من نموذج أولي إلى منصة تعليمية حقيقية

## الوضع الحالي (تم التحقق منه)
- لا توجد قاعدة بيانات: كل المحتوى في `src/lib/data/mockData.ts` + `localStorage` عبر `contentService.ts` و `userService.ts`.
- لا يوجد نظام تسجيل دخول ولا أدوار؛ صفحة `/admin` مفتوحة للجميع وتكتب في متصفح الزائر فقط.
- بنية المحتوى مسطّحة: مسار → دروس، بدون فصول/أجزاء، وبدون تتبّع تقدّم حقيقي.
- لا مدونة ولا عداد زوار.

## المرحلة 1 — تفعيل الخلفية (Lovable Cloud) + المستخدمون والأدوار
- تفعيل Lovable Cloud (قاعدة بيانات + مصادقة + تخزين).
- صفحة `/auth`: تسجيل بالبريد/كلمة السر + Google، وصفحة استرجاع كلمة السر.
- جداول: `profiles` (اسم، صورة، لغة، bio) تُنشأ تلقائيًا عند التسجيل، و`user_roles` منفصل بأدوار `admin | editor | student` مع دالة `has_role` آمنة (منع تصعيد الصلاحيات).
- حماية المسارات: كل صفحات المستخدم تحت بوابة تسجيل الدخول، ولوحة المدير تحت فحص دور `admin`.
- زر الحساب في الشريط العلوي يعكس حالة الجلسة (دخول/خروج/الملف الشخصي).

## المرحلة 2 — بنية المحتوى التعليمي المنظّم
هيكل هرمي حقيقي:

```text
Program (برنامج)
 └── Level (مستوى 1..N)
      └── Course/Path (فصل دراسي)
           └── Chapter (فصل)
                └── Unit/Part (جزء)
                     └── Lesson (درس)
                          ├── Blocks (فقرات قراءة، صورة، كود، فيديو، ملاحظة)
                          └── Questions (اختيار من متعدد، صح/خطأ، ترتيب، إكمال فراغ)
```

- جداول: `programs, levels, courses, chapters, units, lessons, lesson_blocks, questions, question_options`.
- ترتيب (`order_index`)، حالة نشر (draft/published)، شروط فتح (لا يُفتح الجزء التالي إلا بعد اجتياز السابق بنسبة محددة).
- الحقول العامة للقراءة عبر سياسات RLS محدودة، والتحرير للمدير/المحرر فقط.

## المرحلة 3 — تجربة الدرس للطالب (القلب التعليمي)
صفحة درس تفاعلية على غرار Duolingo + قراءة منظمة:
1. عرض الفقرات واحدة تلو الأخرى (تقدّم أفقي في الأعلى).
2. بعد كل مجموعة فقرات: سؤال اختيار الإجابة الصحيحة.
3. تغذية راجعة فورية: صحيح (تأثير + صوت + عبارة تشجيع) / خطأ (شرح مبسّط وإعادة محاولة).
4. نهاية الدرس: ملخص النقاط، XP المكتسب، الدقة %، وزر «الدرس التالي».
- تتبّع في `lesson_progress` و`question_attempts`: حالة، نسبة الصحة، الوقت، عدد المحاولات.
- نظام تنقيط: XP لكل إجابة صحيحة، مضاعف للسلسلة (streak)، خصم بسيط عند تكرار الخطأ، شارات عند إتمام فصل/مستوى، شهادة عند إنهاء المستوى.
- المستويات والرتب تُحتسب من مجموع XP (يُنقل منطق `getLevelInfo` إلى الخادم للمصداقية).

## المرحلة 4 — صفحة المستخدم الخاصة (Dashboard)
- «تابع من حيث توقفت» + خريطة المسار (عقد مضيئة: مكتمل / مفتوح / مقفل).
- إحصائيات: XP، المستوى، السلسلة اليومية، دقة الإجابات، الوقت الأسبوعي (رسم بياني).
- الشارات والشهادات، سجل النشاط، المهمة اليومية، لوحة الصدارة الحقيقية من قاعدة البيانات.

## المرحلة 5 — لوحة تحكم المدير الحقيقية
لوحة كاملة بدل النسخة المحلية الحالية:
- **المحتوى**: إنشاء/تعديل/حذف وإعادة ترتيب البرامج والمستويات والفصول والأجزاء والدروس، محرّر فقرات (Blocks) ومحرّر أسئلة بخيارات وشرح، معاينة قبل النشر.
- **المستخدمون**: قائمة، بحث، تعديل الأدوار، حظر، عرض تقدّم أي طالب.
- **المدونة**: إدارة المقالات والفئات.
- **الإحصائيات**: عدد الزوار، المستخدمون النشطون، الدروس الأكثر إكمالًا، الأسئلة الأكثر خطأً.
- **الإعدادات**: نصوص الواجهة، المهام اليومية، أدوات الذكاء الاصطناعي.

## المرحلة 6 — المدونة
- جداول `posts`, `post_categories`, `post_tags` (عنوان، slug، صورة غلاف، محتوى، حالة، تاريخ نشر، كاتب).
- مسارات: `/blog` (قائمة + فئات + بحث) و `/blog/$slug` (مقال مع SEO كامل: عنوان، وصف، og:image، JSON-LD Article، canonical).
- إدارة كاملة من لوحة المدير.

## المرحلة 7 — عداد الزوار والتحليلات
- جدول `page_views` (مسار، معرف جلسة مجهول، دولة، مرجع، وقت) + جدول تجميعي يومي.
- تسجيل الزيارة عبر Server Function خفيفة (بدون بيانات شخصية).
- عرض: عداد عام في الفوتر (اختياري) + رسوم تفصيلية في لوحة المدير (زوار اليوم/الأسبوع/الشهر، الصفحات الأكثر زيارة).

## المرحلة 8 — الترحيل والصقل
- نقل بيانات `mockData.ts` الحالية إلى قاعدة البيانات كبذور (Seed) داخل الهجرة، مع ترتيبها ضمن مستويات وفصول وأجزاء.
- الاحتفاظ بتقدّم `localStorage` كمرحلة انتقالية ثم دمجه في حساب المستخدم عند أول تسجيل دخول.
- الحفاظ على الهوية البصرية الحالية (Neon Royal) وحقوق HN-Group في الفوتر، وتحديث PWA للعمل دون اتصال مع الدروس المخزّنة.

## تفاصيل تقنية
- TanStack Start + Lovable Cloud؛ كل عمليات القراءة/الكتابة عبر `createServerFn` مع RLS.
- الأدوار في جدول `user_roles` منفصل + دالة `has_role` بصلاحية `security definer` (ممنوع تخزين الدور في `profiles`).
- التحقق من كل المدخلات بـ Zod على الخادم، ومنح صلاحيات `GRANT` صريحة لكل جدول جديد.
- احتساب XP والنجاح يتم على الخادم فقط لمنع التلاعب.
- ترتيب التنفيذ: 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8، مع إمكانية استخدام المنصة بعد كل مرحلة.
